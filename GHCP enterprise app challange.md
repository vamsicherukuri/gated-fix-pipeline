# GitHub Copilot App Enterprise Challenge

I'm planning to participate and win the GitHub Copilot App Enterprise Challenge.

Here is the challenge details:

## Challenge Goal

Identify and showcase repeatable, enterprise-ready workflows that use the GitHub Copilot App to improve how customers, both developers and non-developers, plan, execute, validate, and scale their work.

The GitHub Copilot App brings people, agents, GitHub context, and connected tools into one workspace. The challenge rewards repeatable customer and internal workflow patterns that show how MCAPS & GitHub field teams can improve execution across software delivery, sales, enablement, program management, customer engagement, and other enterprise scenarios.

Winning submissions should answer one question:

> "If GitHub Copilot App is now the workspace for agentic development, what are the enterprise workflows we want customers to copy and our teams to scale?"

## Design Principles

**Stand out with enterprise-ready workflows**
Competitive differentiation through real-world use cases.

Prioritize workflows that clearly demonstrate the GitHub Copilot App's enterprise advantages over Claude Code, including deep GitHub integration, multi-agent collaboration, connected enterprise context, governance, and human review.

**Workflow transformation over net-new**
Participants do not need to create a new product; they need to show a better way for enterprise teams to plan, delegate, validate, review, and ship software work with the GitHub Copilot App.

**Make it repeatable and trustworthy**
Customer repeatability over one-off.

The best submissions should be reusable by account teams, customer success, solution sales, and developer stakeholders as field-ready patterns.

**Delegation with the right review gates**
Strong entries should show how the GitHub Copilot App enables people to delegate more work while retaining oversight at the moments that matter.

## What You Will Build

Submit a repeatable workflow that helps a customer plan, delegate, validate, review, or ship work using the GitHub Copilot App. Not limited to software development workflows. Entries should clearly explain the customer scenario, business value, adoption path, and how field teams can reuse the pattern.

Required submission components:

1. **Project summary** — a short summary explaining the business problem, customer/user persona, GitHub Copilot App workflow pattern, and why the workflow matters (150 words max).
2. **Demo video** — the workflow in action (3 minutes max).
3. **Repo** — code, prompts, instructions, configuration, connected tools, templates, or other workflow assets. Does not need to be production-ready.
   - README should cover: roles, prerequisites, governance considerations, human-in-the-loop model, and success measures where applicable.
4. **Slide deck (1–3 slides)** — workflow architecture or flow, app screenshots where relevant. May also include field/customer feedback and adoption motion.
5. **Competitive positioning paragraph** — how your submission showcases your competitive edge against Claude Code.
6. **[Bonus Points]** Product feedback on GHCP App.

## How to Win

Solutions will be judged on:

| Criteria | Points |
|---|---|
| Enterprise relevance, applicability and customer value | 35 |
| Repeatability and field usability: clear setup, reusable instructions, customer-ready narrative, and adoption path | 20 |
| Governance, security, Responsible AI, and human-in-the-loop design: data boundaries, permissions, policy, review model, and enterprise controls | 20 |
| Clear competitive positioning against Claude Code (e.g., Azure AI Foundry, MCP, multi-agent workflows, repository context) and how your design demonstrated it | 15 |
| Storytelling and demo clarity | 10 |
| **Bonus:** Share product feedback on GHCP App as part of your submission | 5 |
